# Richology 青少年 AI 时代成长图谱网站 Spec

> 状态：Implemented，首版已完成
> 版本：0.1
> 日期：2026-09-22
> 目标：可部署到 Richology 正式域名的首个生产版本

## 1. 产品结论

建设一个中文优先、单页、可交互的 3D 能力图谱网站。整体交互逻辑与 Marble Curriculum 的公开页面同类：用户可以旋转、缩放、筛选、聚焦节点并追溯能力关系；Richology 在此基础上增加“星图 / 地形”双视图，内容、数据模型、品牌、视觉语言和实现代码完全属于 Richology。

首版不是宣传落地页，也不是学生测评系统。它是图谱数据的公共浏览器，并为后续课程设计、教师使用、家长理解和青少年自我探索提供统一入口。

## 2. 已确认范围

### 2.1 必须包含

- 正式域名可部署的生产版本，默认部署在域名根路径，并支持配置子路径。
- 单页 3D 能力图谱；当前读取 4 个领域、12 个二级领域、60 个能力节点和 75 条关系。
- `星图 / 地形` 一键切换。两种视图共享同一份数据和交互状态，不重新加载页面。
- 图谱旋转、缩放、节点悬停、节点选择、返回、视角重置。
- 4 个一级领域筛选；筛选结果不销毁相机位置。
- 节点详情面板，展示定义、边界、可观察行为、E1–E4、证据与反证、人生课题映射、来源和版本。
- `requires`、`supports`、`related_to` 三类关系的说明与聚焦追溯。
- 数据版本、草案状态、使用边界和开放数据入口。
- 桌面、平板和手机适配；键盘、触控、减少动态和屏幕阅读器支持。
- 页面可见文案全部中文，品牌名使用 `Richology`。

### 2.2 首版不包含

- 独立节点详情页或多页内容站。
- 教师、家长、青少年三套独立入口或角色画像。
- 登录、收藏、学习记录、个人测评、评分、排名和推荐算法。
- 课程商城、内容管理后台、评论、表单和用户上传。
- 真实学生案例或任何可识别的未成年人数据。
- AI 对话助手、自然语言搜索，以及与图谱数据无关的装饰性 3D 场景。

## 3. 用户主任务

用户进入页面后，在不学习复杂操作的前提下完成一条探索链：

```text
看见全局结构 → 选择星图或地形 → 选择领域 → 聚焦能力节点 → 理解节点内容
→ 查看直接前置、支持与相关能力 → 沿关系继续探索 → 返回全局
```

教师和课程设计者可以据此确认课程涉及哪些能力及关系；家长和青少年可以理解“下一步可练习什么”，但页面不对个人作测评结论。

## 4. 信息架构与页面布局

### 4.1 桌面端（≥ 1024px）

- 左上：`Richology` 品牌文字、项目名、两行以内的项目说明。
- 图谱上方：`星图 / 地形` 分段控制，默认选中星图。
- 左侧中部：4 个领域筛选器与关系图例。
- 中央至右侧：占可视区约 70% 的 Canvas 3D 图谱。
- 右下：操作提示与“重置视角”。
- 右侧：选择节点后出现详情面板，宽度 360–420px；图谱视口同步收缩，不被面板直接覆盖。
- 顶部右侧：`方法与边界`、`开放数据` 两个文本入口；不建设完整站点导航。
- 底部：数据版本、草案提示、许可证和 GitHub 链接。

### 4.2 移动端（< 768px）

- 顶部保留品牌、项目名和一行说明。
- 领域筛选器横向滚动；操作提示首次显示后可收起。
- `星图 / 地形` 位于顶部工具条，单击即可切换；不放入隐藏菜单。
- 图谱使用主要可视区；单指旋转、双指缩放。
- 节点详情使用可拖动的底部抽屉，提供 40%、75%、全屏三个停靠位置。
- 抽屉打开时保留当前节点在未遮挡区域内；关闭后恢复原相机位置。
- 复杂内容按“概览 / 熟练度 / 证据与边界”分段，不横向塞入桌面式标签页。

## 5. 首屏中文文案

以下文案作为实现基线，可在视觉 QA 时做不改变含义的微调：

- 项目名：`青少年 AI 时代成长图谱`
- 主说明：`从真实任务出发，看见能力之间的关系与成长路径。`
- 数据摘要：`4 个领域 · 12 个能力群 · 60 项能力 · 75 条关系`
- 操作提示：`拖动旋转 · 滚轮或双指缩放 · 点击节点查看详情`
- 筛选标题：`能力领域`
- 关系入口：`关系说明`
- 视图切换：`星图`、`地形`
- 重置按钮：`重置视角`
- 数据入口：`查看开放数据`
- 状态提示：`当前版本为公开草案，不用于标准化测评、排名或筛选。`

计数必须从 `data/manifest.json` 动态生成，不在组件中硬编码。

## 6. 图谱视觉与空间规则

### 6.1 视觉方向

采用 [DESIGN.md](../DESIGN.md) 的“双重能力世界”，禁止沿用 Marble 的紫蓝配色：

- **星图**：近黑 `#111114` 背景，强调节点、关系方向和深度。
- **地形**：矿物纸 `#F1F1EF` 外框与深色抽象地貌，4 个领域形成相连区域，节点像观测点，关系像路径与桥梁。

两种视图共同使用青蓝 `#0CA8D4`、青柠 `#C5EE4C`、珊瑚和琥珀领域色，并保持相同的中文信息层级。地形不得使用写实照片、游戏贴图或不可追溯的生成式背景；所有地貌、节点和路径由确定性布局数据生成。

两张已确认的星图稿与地形稿是桌面主场景的视觉合同，而不只是气氛参考。实现以 1440×900 为主验收视口，并在 1024px 与 390px 复核：

- 星图必须完整呈现四个稳定领域簇、跨域弧线、领域名称，以及每个领域至少 3 个关键能力名称。
- 地形必须呈现一个连续且有厚度的岛屿，包含海岸悬崖、峰谷、植被、节点基座和克制的跨域路径；四个领域属于同一世界，而不是四色矩形分区。
- 星图负责精确阅读关系，常驻关键节点标签；地形负责理解结构，只常驻领域标签，具体能力通过悬停或点击呈现。
- 详情面板打开后，当前节点及其一跳关系仍须处于安全可视区，不能只压缩画布而不调整构图。
- 默认星图、默认地形、选中节点和移动端四种状态纳入视觉回归；功能测试通过不能替代视觉验收。

领域必须同时使用颜色、光环细节和中文标签。节点保持统一的圆点语言，避免几何体随旋转造成视觉失真：

- AI 技能化：青蓝、实心圆。
- 商业化：青柠、细双环。
- 职业化：珊瑚、内核圆点。
- 社会化：琥珀、细光环。

### 6.2 确定性 3D 布局

构建时生成稳定的 `x / y / z` 坐标，不在每次访问时随机布局：

1. 仅用 `requires` 计算前置层级；如果存在环，先收缩强连通分量。
2. 基础节点位于较低层，依赖更多前置能力的节点位于较高层。
3. 4 个领域分布在不同角区，12 个二级领域形成领域内小簇。
4. 使用节点 ID 的稳定哈希添加有限扰动，并通过固定迭代次数完成碰撞分离。
5. `supports` 与 `related_to` 只影响局部靠近程度，不改变前置层级。
6. 节点大小参考 `graph-metrics.json` 的结构指标，但最大直径不超过最小直径的 2.2 倍，避免把“中心性”误读为“重要性”。

布局生成器必须同时输出两组可复现坐标：

- `star_position`：面向精确关系阅读的三维簇状布局。
- `terrain_position`：保留前置层级与领域邻接的地形锚点。

相同数据与相同算法版本必须产生字节一致的坐标文件。两组坐标中的同一节点保持稳定 ID 映射，供视图切换插值。

### 6.3 深度表达

- 主视图由 Three.js/WebGL 完成透视投影、深度测试和实例化绘制；Canvas 2D 兼容模式自行计算透视并按深度排序。
- 远处节点降低亮度与尺寸，不使用高强度模糊。
- 未聚焦时只为核心或悬停节点显示标签；聚焦后显示一跳关系标签。
- 背景可以有极弱网格或颗粒，但不得被误认为数据节点。

### 6.4 地形表达

- 地形由低多边形或平滑简化网格程序化生成，不使用写实地理素材。
- 4 个领域形成可辨认但彼此相连的区域；12 个二级领域形成局部高地或平台。
- `requires` 决定总体海拔层级，基础能力较低、依赖更多前置的能力较高，但界面明确说明海拔不等于价值或难度。
- 跨领域的高置信关系可以表现为桥梁或清晰路径；其余关系仍使用规范线型，避免把所有边都变成道路。
- 地形只提供结构隐喻，不出现山峰排名、终点旗帜、人物等级或唯一登顶路线。

## 7. 交互规范

### 7.1 相机

- 鼠标或单指拖动：旋转。
- 滚轮或双指：缩放；设置合理最小/最大距离，防止穿过图谱。
- 释放：短惯性，最多约 600ms；减少动态模式下无惯性。
- `重置视角`：回到默认角度与缩放，不改变筛选条件。
- 双击/双击触控节点：聚焦相机；单击只选择，不造成突兀飞行。

### 7.2 视图切换

- 单击 `星图 / 地形` 后在 500–800ms 内完成节点位置、相机和背景过渡。
- 保留领域筛选、当前节点、关系高亮、详情滚动位置和节点浏览栈。
- 星图与地形各自保存最近相机角度；切回时恢复该视图的最近视角。
- 切换期间禁止重复触发，但关闭详情、按 `Esc` 和减少动态设置仍立即生效。
- URL 使用查询参数保存可分享状态，例如 `?view=terrain&node=AI-BND-001`；状态切换通过 History API 完成，不重新加载页面。
- 地形无法启用时，切换按钮禁用并说明 `当前设备使用星图兼容模式`，内容浏览不受影响。

### 7.3 悬停与选择

- 悬停节点：显示中文名称、所属二级领域和一行定义；扩大命中区，不扩大视觉节点。
- 选择节点：锁定选中态，打开详情，突出一跳关系，其余节点降到 18–28% 不透明度。
- 点击空白或按 `Esc`：关闭详情并回到上一个图谱状态。
- 详情中的关系节点可继续选择；维护浏览栈，提供 `返回上一个节点`。

### 7.4 领域筛选

- 默认全部开启；按钮显示颜色、形状和中文领域名。
- 单击切换领域；`Alt/Option + 单击` 或长按可单独查看该领域。
- 至少保留一个领域；尝试关闭最后一个领域时显示简短提示。
- 被隐藏领域参与布局但不绘制，避免筛选时图谱整体跳动。

### 7.5 关系语义

- `requires`：`source_id` 需要 `target_id`。聚焦时从 source 指向 target，并在详情中列为“直接前置”。
- `supports`：显示为无箭头短虚线，详情文案为“支持该能力”或“该能力支持”。
- `related_to`：显示为无方向点线，详情文案为“相关能力”。
- “可继续发展”列表通过反向查找 `requires` 得到，不与“直接前置”混用。
- 默认只展开一跳；用户明确选择“查看完整前置链”后才运行广度优先追溯。

## 8. 节点详情

详情面板不创建新 URL 页面，但应更新 URL 查询参数中的 `node`，从而支持刷新与分享。

### 8.1 顶部摘要

- 中文名称、节点 ID、一级领域、二级领域、`draft` 状态和版本。
- 中文定义。
- `直接前置`、`可继续发展`、`支持`、`相关` 数量。

### 8.2 内容分区

1. `概览`：定义、边界、可观察行为、人生课题映射。
2. `熟练度`：E1–E4 全部描述，并注明熟练度不是年龄或人格标签。
3. `证据与边界`：强证据、弱证据/反证、注意事项、来源、版本记录。

来源 URL 必须使用 `https` 并在新标签页打开，带 `noopener noreferrer`。缺失字段时不展示空标题或占位符，而是记录构建警告。

## 9. 状态与异常

- `加载中`：先显示页面框架和简短文字 `正在构建能力图谱…`，不使用无限旋转图标。
- `数据错误`：显示 `图谱数据暂时无法加载`、重试按钮和开放数据链接；不得只留下空白 Canvas。
- `空筛选`：产品逻辑阻止所有领域同时关闭。
- `无关系节点`：正常显示节点内容，并说明 `当前版本尚未记录直接关系`。
- `URL 节点不存在`：忽略无效 hash，显示全局视图和非阻塞提示。
- `WebGL 不可用`：使用 Canvas 2D 星图兼容模式，禁用地形切换；Canvas 也不可用时显示语义化节点列表。
- `减少动态`：无自动入场、无惯性、无相机飞行；关系高亮即时切换。

## 10. 技术方案

### 10.1 栈

- Astro + TypeScript，静态输出。
- Three.js 负责共享 WebGL 场景、相机、节点实例、关系线和程序化地形；不引入 React、Vue 或 D3 运行时。
- Canvas 2D 提供星图兼容渲染，不实现完整地形。
- 构建时数据适配与确定性布局脚本；运行时只读取面向网站的紧凑 JSON。
- CSS 自定义属性实现色彩、排版、断点和减少动态。

选择原因：单一星图使用 Canvas 2D 已足够，但星图与程序化地形需要共享相机、三维坐标、深度遮挡和连续切换。Three.js 在此范围内能明显降低自研 WebGL 的复杂度，并保证两种视图使用同一渲染状态；通过按需导入、实例化绘制和静态数据控制包体与性能。

### 10.2 建议目录

```text
site/
├── astro.config.mjs
├── package.json
├── public/
│   └── data/graph.json
└── src/
    ├── components/
    │   ├── GraphCanvas.astro
    │   ├── GraphControls.astro
    │   ├── NodeDetails.astro
    │   └── AccessibleGraphIndex.astro
    ├── lib/
    │   ├── camera.ts
    │   ├── graph.ts
    │   ├── interactions.ts
    │   ├── renderer.ts
    │   ├── star-view.ts
    │   ├── terrain-view.ts
    │   └── canvas-fallback.ts
    ├── pages/index.astro
    └── styles/global.css
tools/
├── build_web_graph.py
└── build_graph_layout.py
```

网站放在 `site/`，不改变现有数据目录的公共契约。构建脚本只读取已验证的数据并生成派生文件；生成文件包含源图谱版本与布局算法版本。

### 10.3 数据输入

必须读取：

- `data/domains.json`
- `data/competencies.json`
- `data/dependencies.json`
- `data/graph-metrics.json`
- `data/manifest.json`

构建前先运行 `tools/validator/validate.py`。任何缺失节点引用、非法关系类型、重复 ID 或 manifest 计数不一致均使网站构建失败。

### 10.4 数据输出

`site/public/data/graph.json` 至少包含：

- `meta`：图谱版本、生成时间、计数、布局版本。
- `domains`：领域与二级领域中文名称、颜色和标记。
- `nodes`：网站需要的节点字段、图指标、`star_position` 和 `terrain_position`。
- `edges`：source、target、type 与中文 rationale。

不得在前端复制维护第二份能力内容；派生数据每次由源数据生成。

## 11. 性能、兼容与隐私

### 11.1 性能预算

- 首屏可交互 JavaScript：目标 ≤ 220KB gzip，不含图谱 JSON；地形模块延迟加载。
- 图谱派生 JSON：目标 ≤ 250KB gzip。
- LCP ≤ 2.5s、INP ≤ 200ms、CLS ≤ 0.1（生产构建、主流中端设备）。
- 星图桌面交互目标 60fps，地形和移动端最低可接受 30fps；设备像素比上限为 2。
- 地形采用细节层级：低性能设备减少网格密度、植被/装饰和阴影，不减少节点与关系数据。
- 页面不可见时暂停动画；静止且无交互时停止 `requestAnimationFrame` 循环。

### 11.2 浏览器

- 最近两个主要版本的 Chrome、Edge、Firefox、Safari。
- iOS Safari 16.4+，Android Chrome 近两年版本。
- 不支持 Canvas 或低性能环境时自动使用语义化列表，不阻断内容。

### 11.3 隐私与安全

- 首版无账号、Cookie、用户画像和第三方分析脚本。
- 不收集青少年个人信息，不上传交互记录。
- 使用严格 CSP；所有可点击外链显式声明目标。
- 若未来加入统计，必须另行评审隐私、未成年人保护与同意机制。

## 12. SEO 与分享

- 页面语言 `zh-CN`，标题为 `Richology 青少年 AI 时代成长图谱`。
- 描述说明图谱用于能力探索与课程设计，不用于标准化测评。
- canonical、Open Graph、favicon 和站点图使用 Richology 自有资产；首版没有图形 Logo 时使用文字与纯色生成的分享图。
- 节点 hash 不生成独立搜索索引页面；页面内提供可抓取的能力名称摘要。

## 13. 测试与验收

### 13.1 自动检查

- 现有 Python validator 全部通过。
- 数据适配、关系方向、反向“可继续发展”、布局确定性有单元测试。
- 相机、命中测试、筛选状态、双视图坐标和 URL 状态有单元测试。
- Playwright 覆盖旋转、缩放、双视图切换、状态保持、筛选、选择、关系跳转、返回、刷新恢复和移动端抽屉。
- axe 或等价工具无严重/高等级无障碍问题。
- Astro 生产构建、链接检查与 Lighthouse CI 通过。

### 13.2 视觉与内容验收

- 1440×900、1280×800、390×844、360×800 四种视口截图检查。
- 4 个领域在正常视觉、常见色觉差异模拟和高对比模式下均可区分。
- 所有面向用户文案为中文；`Richology`、节点 ID 与必要许可证名除外。
- 60 个节点均可通过 Canvas 或语义化列表打开；详情字段与源 JSON 一致。
- 三类关系的方向和线型与规范一致，完整前置链无死循环。
- 星图与地形切换不丢失筛选、当前节点、详情状态和浏览历史；不支持 WebGL 时兼容模式可用。
- 不出现 Marble 标志、文案、配色、字体、图片、源代码或像素级复制。

### 13.3 完成定义

满足以下条件才可称为“现在可以做网站并准备上线”：

1. 本 Spec 获得确认。
2. 页面、数据构建脚本和测试均在仓库中。
3. validator、单元测试、端到端测试、链接检查和生产构建通过。
4. 桌面与移动端视觉 QA 通过，无阻断级无障碍问题。
5. 生产预览经用户验收。
6. 自有域名 DNS、HTTPS、canonical 和部署回滚方案配置完成。

## 14. 部署策略

- 输出纯静态站，可部署到 Vercel、Netlify、Cloudflare Pages 或等价平台。
- 首次实现保持平台中立；在用户提供具体域名与托管平台后补充平台配置。
- 生产部署采用 GitHub `main` 分支触发；预览部署用于验收。
- 发布前保留上一生产版本，可在一次部署内回滚。
- 域名切换属于单独上线步骤，不在开始编码时修改现有 DNS。

## 15. Clean-room 边界

Marble 仅作为公开交互行为与信息架构参考。实现必须从本 Spec 和 Richology 数据独立编写，不复制 Marble 页面源代码、未开源布局数据、品牌资产、字体、文案和视觉细节。`withmarbleapp/os-taxonomy` 的数据/文本许可不自动授予 Marble 网站代码或品牌使用权。

## 16. 确认后的实施顺序

1. 搭建 `site/`、测试与构建命令。
2. 编写数据适配和确定性 3D 布局生成器。
3. 实现共享 WebGL 场景、相机、输入和 Canvas 兼容层。
4. 实现星图视图与程序化地形视图。
5. 实现视图切换、筛选、节点详情、关系追溯与 URL 状态。
6. 实现移动端与无障碍替代视图。
7. 完成视觉精修、性能优化和全套验证。
8. 创建生产预览，用户验收后绑定正式域名。
