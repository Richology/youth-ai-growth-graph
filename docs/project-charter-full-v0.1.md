# Richology 青少年 AI 时代成长图谱

## 项目总纲与开源路线图 v0.1

> 状态：Draft / Working Paper
> 定位：面向青少年 AI 创造与商业化教育的开放框架、能力图谱与实践方法论
> 核心主张：不只展示学生做出了什么，更说明作品背后哪些能力得到了发展，并提供可核验的证据。

---

## 1. 项目身份

- **项目总名**：Richology 青少年 AI 时代成长图谱
- **GitHub 仓库建议名**：`youth-ai-growth-graph`
- **核心数据系统**：青少年 AI 商业化能力图谱
- **首份理论文档**：《青少年 AI 时代成长图谱：开放框架与方法论 v0.1》
- **当前发布性质**：开放框架与实践型工作论文，而非已经获得学术共同体认可的标准或权威白皮书
- **主要对象**：课程设计者、教师、青少年教育机构、家长、研究者，以及青少年学习者

## 2. 项目要解决的问题

传统课程常用“上了什么课、做了什么作品”描述学习结果，但缺少一套结构，回答以下问题：

1. 青少年在 AI 时代究竟需要发展哪些能力？
2. 各项能力之间有什么依赖关系和成长路径？
3. 一门课程或一个项目覆盖了哪些能力？
4. 学生的作品、过程和反思能证明哪些能力变化？
5. 教师怎样据此设计课程，家长怎样理解作品背后的成长？
6. AI 创造和商业实践怎样与人的财富、健康、关系三大人生课题相连接？

本项目不把商业化狭义理解为赚钱技巧，而把它视为：发现真实问题、创造价值、服务他人、接受反馈并持续迭代的完整实践过程。

## 3. 核心概念模型

### 3.1 三大人生课题：长期价值方向

- **财富**：创造价值、交换价值、管理资源，并逐渐建立独立生活的能力。
- **健康**：管理身体、情绪、注意力与节奏，形成可持续发展的基础。
- **关系**：理解他人、有效协作、建立信任，并在社会中负责任地行动。

三大课题不是三门课程，也不意味着一节课能直接改善财富、健康或关系；它们是能力培养最终服务的长期人生方向。

### 3.2 四个能力领域：图谱的一级结构

| 能力领域 | 核心问题 | 初步二级领域 |
|---|---|---|
| AI 技能化 | 怎样把 AI 变成人的基础能力与创造杠杆？ | AI 边界、人机沟通与协作、判断与纠偏 |
| 商业化 | 怎样把想法转化为真实世界中的价值？ | 需求洞察、产品构建、市场验证 |
| 职业化 | 怎样可靠、专业、持续地完成一件事？ | 项目管理、专业沟通、自我驱动 |
| 社会化 | 怎样理解他人、参与协作并承担责任？ | 社会感知、协作实践、规则意识 |

### 3.3 四种实践深度：创造到创业

- **创造**：产生新的想法、组合与解决方案。
- **创作**：把想法表达为可感知、可使用的作品。
- **创新**：让作品在真实情境中产生新的有效价值。
- **创业**：围绕价值持续组织资源、承担责任并建立可持续交换。

这四者不是与四个能力领域平行的分类，而是学生运用多种能力、不断进入真实世界的实践深度。

### 3.4 基本学习循环

`发现真实问题 → 与 AI 协作 → 做出作品 → 进入真实场景 → 获得反馈 → 调整迭代 → 沉淀能力证据`

## 4. 三个彼此连接但不能混用的组成部分

| 组成部分 | 回答的问题 | 主要内容 | 主要产物 |
|---|---|---|---|
| 开放框架 | 我们怎样理解青少年在 AI 时代的成长？ | 价值观、概念边界、总体结构、设计原则、伦理与治理 | 工作论文、框架图、术语表 |
| 能力图谱 | 学生具体需要发展什么，各能力如何关联？ | 能力节点、层级、依赖、熟练度、证据、反证、情境映射 | JSON 数据、Schema、可视化图谱 |
| 方法论 | 教师和学生怎样使用这张图谱行动？ | 课程设计、项目设计、AI 协作、观察取证、反思评价、家长沟通 | 模板、指南、案例、工具 |

一句话概括：**开放框架画出世界的边界，能力图谱标出其中的地点和道路，方法论告诉人们怎样在这张地图上行动。**

## 5. 能力节点的最小数据结构

每个能力节点至少包含：

- 唯一 ID 与中英文名称
- 所属一级、二级领域
- 清晰定义及适用边界
- 前置能力与相关能力
- 可观察行为
- 熟练度等级
- 可以作为证明的学习证据
- 容易造成误判的反证或限制
- 适用的项目情境
- 与财富、健康、关系的可能联系
- 版本、来源与修订记录

需要严格区分“能力”“知识”“任务”“作品”“证据”。作品不是能力本身，只是能力证据的载体之一。

## 6. 图谱的核心用法

### 6.1 课程设计

从目标能力反推学习任务、项目情境、AI 工具、评价证据和反思问题，避免课程只围绕工具功能或作品形式展开。

### 6.2 课程标注

标明每节课：重点发展哪些能力、依赖哪些前置能力、产生什么证据，以及课程覆盖的深度，而不只是给能力贴标签。

### 6.3 学习证据与家长沟通

把“学生做了一个作品”转化为“学生在何种情境下完成了什么行为，形成了什么证据，对应哪些能力及其当前水平”。避免用一次作品给孩子下永久结论。

### 6.4 教师专业成长与体系建设

让课程、案例、评价和理论使用同一套语言，逐渐形成可积累、可讨论、可修订的专业系统。

## 7. 与 Marble os-taxonomy 的关系

Marble 的开源项目主要提供了“知识／能力图谱的数据层与技术规范”：主题节点、依赖关系、课程映射、聚类、JSON Schema、校验机制和开放许可。

本项目可以借鉴它的：

- 节点与关系分离的数据结构
- 稳定 ID 和机器可读格式
- Schema 校验及贡献流程
- 数据版本管理和可视化思路

但不直接复制其学科知识分类。本项目需要自行构建青少年 AI 创造与商业化教育的概念、能力、证据和方法体系。相较 Marble，本项目计划同时开放框架、图谱和方法论。

## 11. 网站与可视化原则

- **3D 模式**：用于呈现整体结构、关系密度和品牌吸引力，适合传播与探索。
- **2D 模式**：用于搜索、筛选、课程映射、能力对照、证据记录和家长报告，是主要工作界面。
- **移动端**：默认采用 2D 或卡片视图，不强求 3D。
- **建设顺序**：先完成概念、规范和首批数据，再开发视觉效果；不能让图谱只是炫酷但无法用于课程决策。

## 12. 分阶段路线图

### M0：项目立项

- 确定名称、定位、受众、非目标和语言策略
- 确定多许可方案、治理原则与未成年人数据边界
- 创建 GitHub 仓库与基础文件

### M1：开放框架 v0.1

- 完成术语表和工作论文目录
- 明确三大人生课题、四个能力领域、四种实践深度之间的关系
- 建立原则／观察／假设／证据的陈述规范

### M2：能力图谱 v0.1

- 形成 4 个一级领域、12 个二级领域
- 先发布约 48–60 个能力节点
- 定义关系类型、熟练度、证据与反证
- 发布 JSON Schema、样例数据与校验工具

### M3：应用方法论 v0.1

- 课程映射模板
- 项目设计模板
- 学习证据记录模板
- 家长成长报告模板

### M4：公开评议

- 使用 GitHub Issues、Discussions 和 RFC 接收反馈
- 邀请教育、AI、创业、儿童发展和伦理领域人士审阅
- 所有重要修改保留理由、版本和贡献记录

过去的授课经验用于解释框架如何形成，不作为证明图谱正确的验证数据。

### M5：交互网站

- 先完成实用的 2D 搜索、筛选和映射
- 再增加桌面端 3D 探索模式
- 数据始终来自同一个开放图谱仓库

### M6：稳定发布与长期研究

- 条件成熟后发布白皮书 v1.0
- 制作面向家长和公众的橙皮书
- 积累足够的匿名数据与研究能力后，再考虑年度蓝皮书

## 13. v0.1 的明确非目标

- 不把图谱宣称为经过验证的心理测评或人才测评标准
- 不对学生形成永久性、标签化的能力判断
- 不收集或公开可识别未成年人的原始学习数据
- 不追求一次覆盖所有年龄、学科和商业情境
- 不先做复杂网站，再反向拼凑理论和数据
- 不把“赚到钱”作为商业化学习的唯一成功标准
