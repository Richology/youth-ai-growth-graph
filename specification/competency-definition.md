# 能力节点定义规范 v0.1

## 1. 什么是能力

本项目将能力定义为：

> 学习者能够在一类情境中，调动知识、技能、判断与态度，持续采取有效行动并对结果负责的可能性。

能力不是一次表现，也不是抽象人格词汇。它通过行为表现出来，但不能被单个行为完全代表。

## 2. 五类对象必须分开

| 对象 | 例子 | 是否是能力节点 |
|---|---|---|
| 知识 | 知道大语言模型可能产生幻觉 | 否，可作为能力所需知识 |
| 工具 | 会打开 ChatGPT 或调用某个按钮 | 否，工具会快速变化 |
| 任务 | 为一个产品写宣传文案 | 否，是能力应用的情境 |
| 作品 | 一份产品介绍页 | 否，是潜在证据载体 |
| 能力 | 能识别并核验 AI 输出中的不确定信息 | 是 |

## 3. 节点纳入标准

候选节点至少满足以下条件：

1. **可行动**：名称或定义指向学习者能够采取的行动。
2. **可观察**：能够列出至少两个可观察行为。
3. **可发展**：可以通过任务、反馈与反思获得进步。
4. **可迁移**：不局限于一个软件、一次活动或一个行业。
5. **可区分**：与相邻节点具有可以说明的边界。
6. **粒度适中**：通常可在多个项目中反复练习，而不是大到无法教学或小到只是操作步骤。
7. **适合青少年**：发展要求与 12–18 岁学习者的经验和责任范围相适应。

## 4. 命名规则

- 中文名称优先采用“动词＋对象”，如“识别 AI 能力边界”。
- 避免“优秀”“强大”“高情商”等价值判断词。
- 避免使用具体产品名，如“熟练使用 ChatGPT”。
- 避免把结果命名为能力，如“创业成功”“获得收入”。
- 英文名表达同一含义，不追求逐字翻译。

## 5. ID 规则

格式为：`一级领域-二级领域-三位序号`。

```text
AI-BND-001
BIZ-NED-001
PRO-PJM-001
SOC-AWR-001
```

一级领域代码：

- `AI`：AI 技能化
- `BIZ`：商业化
- `PRO`：职业化
- `SOC`：社会化

## 6. 节点字段

| 字段 | 含义 |
|---|---|
| `id` | 永久唯一标识 |
| `version` | 节点自身版本 |
| `status` | proposed、draft、stable 或 deprecated |
| `name` | 中英文名称 |
| `domain_id` | 所属一级领域 |
| `subdomain_id` | 所属二级领域 |
| `definition` | 能力的正面定义 |
| `boundaries` | 不包含什么、与相邻节点如何区分 |
| `observable_behaviors` | 可观察行为，至少两项 |
| `proficiency_descriptors` | E1–E4 的具体表现 |
| `evidence_guidance` | 推荐证据、弱证据与反证提醒 |
| `life_account_links` | 与人生课题的非因果映射 |
| `claim_status` | principle、observation、hypothesis 或 evidence |
| `sources` | 来源、参考或形成说明 |
| `change_log` | 版本修改记录 |

## 7. 拆分与合并判断

出现以下情况时考虑拆分：

- 一个节点包含两个可以独立教学和观察的动作；
- 不同熟练度描述实际上在评价不同能力；
- 所需前置能力或证据类型明显不同。

出现以下情况时考虑合并：

- 两个节点在多数课程中总是同时出现；
- 可观察行为和证据高度重叠；
- 两者的区别只能依赖措辞，而无法形成不同教学设计。
