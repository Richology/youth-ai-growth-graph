# 关系类型规范 v0.1

## 1. `requires`

**含义**：发展目标能力时，来源能力通常是必要基础。

```text
source --requires--> target
```

记录方式表示“source 需要 target”。例如：

```text
验证产品假设 --requires--> 定义可验证问题
```

使用条件：

- 缺少目标能力时，来源能力在多数相关情境中难以稳定表现；
- 能说明依赖成立的情境；
- 避免形成循环依赖。

## 2. `supports`

**含义**：来源能力能显著帮助目标能力发展，但不是必要条件。

```text
source --supports--> target
```

该关系只说明促进作用，不表示固定学习顺序。

## 3. `related_to`

**含义**：两个能力存在重要联系，但目前不主张方向、必要性或先后顺序。

这是对称关系。数据中只保留一条记录，按节点 ID 字母顺序存储，以避免重复。

## 4. v0.1 暂不启用的关系

- `is_a`：能力节点暂不建立复杂继承体系；
- `causes`：当前证据不足以声明教育因果；
- `measured_by`：本项目尚未建立标准化测量工具；
- `mastered_before`：熟练度具有情境性，不采用绝对掌握语言。

## 5. 每条关系的必要字段

- `id`
- `source_id`
- `target_id`
- `type`
- `rationale`
- `contexts`
- `status`
- `version`
- `sources`

## 6. 质量检查

- `requires` 不得指向自身，也不得形成环；
- `supports` 不应被误写成先修关系；
- `related_to` 不得同时存储正反两条；
- 关系必须有理由，不能只凭概念相似建立；
- 删除关系时保留变更记录。
